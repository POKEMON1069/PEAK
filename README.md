# Aayushman Chandra — digital ecosystem

A personal site with three real products embedded in it, all running on the same
design tokens, the same navigation and the same motion language:

| Route           | What it is                                                                    |
| --------------- | ----------------------------------------------------------------------------- |
| `/`             | Portfolio: hero, about, interests, focus, stack, work, exploring, contact      |
| `/skibidispin`  | A working decision wheel — real physics, real winner, saved entries            |
| `/berty`        | An audio player with a real queue, transport, seek, volume and three surfaces  |
| `/totem`        | Eleven interactive UI primitives with a live preview and the code beside each  |

Everything is static-rendered, self-hosted and dependency-light. There are no
runtime requests to font CDNs, icon CDNs, stock-photo services or audio hosts.

---

## Running it

```bash
npm install
npm run dev        # http://localhost:3000
```

Other scripts:

```bash
npm run build             # production build (all routes prerender statically)
npm run typecheck         # tsc --noEmit
npm run lint              # eslint, via next lint
npm run verify:wheel      # 400k+ geometry checks on the shared rotation maths
npm run verify:clipboard  # tests for the clipboard fallback chain
npm run check:determinism # guards against hydration-unsafe render values
npm run verify            # all of the above, in one go
```

## How the interactive parts actually work

### SkibidiSpin — `/skibidispin`

The wheel does not "pick a name and animate somewhere". A slice is chosen at
random, the rotation that places that slice's centre under the pointer is solved
for, the wheel animates there, and **the winner is then re-derived from the final
angle**. The label you see under the pointer is the label that gets announced.

- Rotation lives in a Framer Motion value, so the same number drives the SVG,
  the tick sounds and the result.
- Clicks are Web Audio oscillators (pitch follows the remaining speed), not
  sample files.
- Entries, the retire-the-winner toggle and the sound preference persist in
  `localStorage`. Pasted comma/newline lists add several entries at once.
- The maths is in `lib/ring.ts` and is verified by `scripts/verify-wheel-math.ts`
  (`npm run verify:wheel`), which proves for every entry count from 2 to 40 that
  the wheel stops **centred** on the chosen slice — never on an edge, where a
  sub-pixel difference could flip the result — and that every spin travels
  forward by at least the intended number of turns.

### Berty — `/berty`

One `<audio>` element, created on mount and owned by a provider:

- `play`/`pause` DOM events are the source of truth for `isPlaying`, so the
  on-screen transport and the OS media keys can never disagree.
- Queue, previous/next, seek, volume, mute, shuffle and an `off → all → one`
  repeat mode, plus Media Session metadata and action handlers.
- Progress is sampled on `requestAnimationFrame` while playing (`timeupdate`
  only fires a few times a second), so the bar moves smoothly.
- Three surfaces — Light, Dark, AMOLED — each with its own explicit palette in
  `components/berty/berty-player.tsx`. Volume and surface persist.
- If a file will not load or decode, the player says so instead of pretending.

The three tracks are synthesised instrumental loops generated by
`scripts/generate-demo-audio.py` (standard library only) and committed as WAV
files in `public/audio`. They are labelled as demo material everywhere they
appear in the UI. To use real audio, drop files into `public/audio` and update
`data/berty-tracks.ts`.

```bash
python3 scripts/generate-demo-audio.py   # regenerate the loops
```

### Totem.components — `/totem`

Eleven primitives, every one interactive on the page: Button, Switch, Segmented
control, Tabs, Accordion, Slider, Tooltip, Toast, Skeleton, Dialog, Carousel.
Each card toggles between the live preview and the usage that produced it, with
a copy button.

The ones worth reading:

- **Dialog** traps Tab, closes on Escape, locks scroll, and restores focus to
  its trigger. Scroll locking also pauses Lenis (see `lib/scroll-lock.ts`).
- **Tabs** and **Segmented control** use roving `tabindex` with arrow-key
  navigation and full ARIA roles.
- **Carousel** is a drag surface with inertia; each slide rotates, scales and
  fades by its distance from the centre, and the strip springs to the nearest
  slide on release.
- **Toast** keeps a real queue — three on screen, auto-dismiss, timers cleaned
  up on unmount.
- **Copy buttons** degrade instead of throwing. The async Clipboard API is
  blocked by permissions policy in a sandboxed frame (which is exactly how this
  site gets previewed or embedded), so `lib/clipboard.ts` asks the Permissions
  API first, falls back to `document.execCommand("copy")`, and if everything is
  blocked it selects the code and says "press ⌘C" rather than logging an error.

### Design tokens

Every colour is an HSL custom property in `app/globals.css`, exposed to Tailwind
as semantic names (`background`, `surface`, `border`, `muted`, `accent`,
`success`, `warning`, `error`). Light and dark are one variable swap, applied
before first paint by a small inline script in `app/layout.tsx`, so a dark-mode
visitor never sees a light flash.

### Render determinism

`Math.sin`, `cos`, `tan`, `exp`, `log`, `pow` and `hypot` are *implementation
defined* in their last bits: Node and the browser genuinely disagree, and a
one-ulp difference in an SVG attribute is a hydration mismatch React refuses to
patch up. So no trigonometry runs during render anywhere in this project.

- The wheel's wedge outlines and the interests ring's unit vectors are
  pre-computed literals (`components/skibidispin/wedge-paths.ts`, `UNIT` in
  `components/home/interests.tsx`); positioning is multiplication, which IEEE-754
  specifies exactly.
- `scripts/check-render-determinism.mjs` enforces this: it fails on any
  transcendental call in a rendered module (unless allowlisted with a reason
  showing it never reaches serialized markup), fails if the ring's vector table
  drifts from `data/interests.ts`, and fails if the prerendered HTML contains an
  un-rounded float in an SVG geometry attribute.

Motion uses one easing language (`cubic-bezier(0.16, 1, 0.3, 1)` for entrances,
springs for anything draggable) and every animation has a reduced-motion branch.
Reduced motion is read through `lib/use-media-query.ts`, which uses
`useSyncExternalStore` with a server snapshot of `false` — Framer Motion's own
`useReducedMotion` reads the media query during the first render, which makes the
server and client disagree for those visitors.

## What is deliberately not here

- **No invented statistics.** No "99% satisfaction", no counters, no client
  logos. There is nothing to back them.
- **No testimonials.** Nobody said those things, so the space holds
  "Currently exploring" — what I am actually reading and thinking about.
- **No stock photography.** Project artwork is SVG generated from each project's
  accent hue; the interests carousel is text on a ring, not photos.
- **No external links that open new tabs**, and no fake embed. The three
  products are routes on this site.
- **No fake data.** Berty's library is honestly labelled as generated demo
  loops; Totem ships eleven primitives, not "hundreds of components".

## Verified before handing over

`npm run verify` runs the lot: types, lint, 402,473 rotation-geometry checks, 20
clipboard checks, a render-determinism audit and a production build with all
four routes prerendering. The rendered HTML of every route was also checked for the expected
structure — six wheel slices with six labels, eleven primitives, the full queue,
no third-party requests, no `target="_blank"`, and no engine-dependent geometry.

Interactive behaviour (spinning the wheel, dragging, playback) was reviewed from
the code rather than clicked through in a browser: this build environment has no
browser available. The dev server is running for a live look.
